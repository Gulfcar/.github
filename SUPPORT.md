# Gulf Car Repository Support

For repositories that do not define a more specific support process:

- Product bugs and reproducible software defects should be filed using the repository's Bug template.
- Feature requests should use the Feature template.
- Refactoring, architecture, maintainability, and reliability work should use the Technical Debt template.
- Operational incidents affecting a live service should use the company's approved internal incident/support channel first, then be documented in GitHub when appropriate.
- Security vulnerabilities, exposed credentials, and exploitable details must follow `SECURITY.md` and must not be posted in normal Issues.

When filing a normal Issue, include the affected repository/module, expected behavior, actual behavior, reproduction steps, environment, and evidence that does not contain secrets or personal data.
